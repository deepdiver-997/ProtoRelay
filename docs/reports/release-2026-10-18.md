## 真实协议验收

使用现有测试账号，通过验证服务端证书的 SMTPS 465 登录并发送一封含三个附件的邮件，
一个收件人为用户指定的 QQ 邮箱，另一个为本地抄送。首轮代码版本 `6427a274c913` 的主站及边缘 outbox 均为 SENT，
最终 DATA 响应码 250；收件人另行确认 QQ 收件箱收到且三个附件齐全。
此前有过通信往来可能影响 QQ 分类，此结果不能外推到陌生企业收件人。

第二封经主站向可信边缘提交，再由边缘 DKIM 签名、通过公网 SMTP 25 回投主站，
用于验证外部入站、正文持久化和 IMAP 读侧，而非只测试本地收件人快捷路径。

两封本地收件均以 IMAPS 993 实际登录、SELECT、UID FETCH BODY.PEEK[] 取回，
由 Python 标准库独立解析 MIME 并解码；文件名、长度、SHA-256 全部一致。
首轮检查过 BODYSTRUCTURE 存在及单独 BODY.PEEK[4] 的 PNG 内容，但没有独立验证附件发现，
因此漏掉下文手机补测暴露的字段错位，不能把首轮结果视为客户端附件识别通过。
回投原始邮件用 dkimpy 及公开 DNS 独立验签成功，未使用服务器自己的验签结论自证。

## 手机客户端补测

用户随后反馈手机取刚才的邮件失败。日志显示认证成功，随后请求
`UID FETCH <uid> (BODY.PEEK[2] BODY.PEEK[1])` 并断开重试；标准库复现确认只返回第一段，
此前单 section 的验收不足以覆盖该路径。`8ec160e` 修复 FETCH 只保存单个节号的问题，
按顺序返回所有请求段，保留完整 MIME 给混合 BODY[]/BODYSTRUCTURE 请求使用。
专项按 literal 声明长度消费并比较各段全文，修复前缺项断言失败、修复后通过。
`78279b4` 同时修正退出记录：现有策略本来就是所有非正常 LOGOUT 均保存，但认证状态
未及时同步导致误标 auth:no。现在立即同步状态、脱敏 LOGIN/PLAIN 凭据、限制 trace
目录/文件为 0700/0600，失败有日志；保留 64 KiB/300 份上限。旧代码专项的脱敏、认证
标记和文件权限三项均失败，修复后三项通过，正常关闭不新增文件。
阶段版本 `78279b4b528c` 部署后，标准库实际复验 993 TLS 和 143 STARTTLS：
同次取 2、1、完整 BODY[] 与 BODYSTRUCTURE，三个 literal 均完整、独立解码内容一致。
另实际制造已认证但未 LOGOUT 的关闭，确认 auth:yes、凭据脱敏、保留普通命令、文件
0600/目录0700；正常 LOGOUT 对照不生成文件。用户随后确认正文恢复正常；

## 验收发现的既有缺口

1. **SMTP 到 Webmail 的独立附件衔接未完成。** SMTP 将所有附件字节保存在完整 MIME 中，
   因而 SMTP/IMAP 和 QQ 收发正确。但轻量解析器只在 DATA_END 记录最后一个附件占位，
   当前查库每封仅有一条空路径、0 字节元数据，没有完整独立附件文件/索引。
   Webmail 下载依赖有效索引和对象，浏览器 fixture 预置了这些数据，不能证明实际入站
   已完成提取。后续需补多附件、中文/RFC 2231 文件名、嵌套 MIME 和失败清理的端到端验收。
2. **DATA_END 验证结果应用未完成。** 当前会话保存 DKIM/DMARC 计算结果，但没有据 hard
   结果拒收，也没有调用认证结果头构造函数写入最终 MIME。回投邮件存在有效 DKIM，
   但没有服务器生成的 Authentication-Results，与源码一致。MAIL FROM 的 SPF hard
   拒收是另一条已实现路径。还需补 hard 失败、缺失依赖和临时 DNS 错误测试。
3. **AUTO AUTH 的 PTR/EHLO 免认证未实现。** 当前会话 trust flag 没有置真路径；全局 auto
   实际仍要求 AUTH。公开 MTA 端口使用 off、提交端口使用 on 的显式策略不依赖此功能。

以上均可在本轮之前的代码中定位，本轮没有扩展这些功能。相关当前文档已更正：
[Webmail 契约](../mail-system/architecture/webmail-api.md)、
[入站验证](../mail-system/architecture/inbound-verification-flow.md)、
[主架构](../architecture/ARCHITECTURE.md)。这次通过的是上述 SMTP/IMAP 附件路径，
不能据此宣布 Webmail 附件链路和入站强制验证全部完成。
